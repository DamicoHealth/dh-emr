DH EMR Field guides

Admin guide

For the person who runs DH EMR Field for a team: holds the admin device, keeps the clinic lists and forms right, looks after backups. Everyday entry is in the user guide, one device in Getting started, the organization's own cloud project in the cloud sync guide.

Field has no accounts. The admin is a device, not a person, and every setting here is changed on that device under Settings.

Admin device, standard device

The setup wizard asks "What is this device allowed to do?". The This device card under Settings shows the answer on its Role row.

Wizard choiceRole row
Enter and view records (most devices)Standard
Also change the form and clinic settings for everyoneAdmin

Keep one or two admin devices with the people who run the clinic; make every other device standard.

Admin device onlyAny device
Clinic lists (sites, clinicians, complaints, procedures, referral destinations); the formulary and lab test panel, including reference ranges; diagnosis quick-picks and prescription presets; form templatesRenaming the device, connecting to a cloud, syncing, backup, restore, import

On a standard device the admin controls are visible but off, with the reason in every disabled control's hover text: "Only an admin device can change this. This device is set to standard." Each card says the same in a note, and the template editor and reference range editor open with a "Read only" banner.

No control in the app changes a device's role after setup. On a cloud device the role in the project's devices table counts: change the row and the device adopts it on its next sync (the cloud sync guide has the query). A device set up on its own keeps the wizard's choice.

Clinic lists

The Clinic lists card fills the pick lists on the visit form. Each list is a text box with its own save button.

ListSave button
Clinic or site namesSave sites
CliniciansSave clinicians
Complaints (the buttons under the Chief concern box)Save complaints
ProceduresSave procedures
Referral destinationsSave referral destinations

  1. On an admin device, edit the box: one entry per line, and commas belong inside an entry. "Grace N., clinical officer" is one clinician. Blank lines are dropped and duplicates removed.

  2. Tap the list's save button.

    "Saved 3 sites. Reopen the visit form to see them." A visit form already open keeps the old list until it is reopened.

Sites and clinicians can never be empty, or no visit could save: "You need at least one site. An empty list would block every save.", and the same for clinicians. The other lists refuse too: "This list cannot be saved empty. One complaint per line."

Until real sites and clinicians are set, every visit is filed under "Site A" and "Physician A", and Settings shows a red warning: "This device is still filing records under placeholder names." Fix this before the first day of entry; placeholder names are no use in a report.

On a cloud team, edit the lists on an admin device. A standard device's lists are replaced by the organization's on its next sync, so there is no point editing them there.

Form templates

The Form templates card lists each form as "On" or "Off" and has one button, Open the template editor. A brand-new organization has one form, already on.

The editor is a panel headed Form templates. Every change saves as you make it (the header reads "Saving…", then "Saved") and reaches everyone on the next sync. Tap Close when done; there is nothing to discard.

On a cloud device that has not synced yet, the editor refuses to write: "Form settings have not reached this device yet".

"Your organization's form has not synced to this device yet. Editing is turned off until it arrives, because saving now would replace your organization's real form with an empty one. Sync this device, then come back." That guard protects the whole team; do not work around it.

Forms

Each form has an editable name box, an On checkbox, and the buttons Sections, Duplicate and Delete. Every visit keeps the name of the form it was filed under, so old visits are never affected by what follows.

Turn on or offThe On checkbox decides whether the form is offered for new visits. With more than one on, a new visit shows a Form template list at the top.

Visits already filed under it keep their answers and their template name. The form just stops being offered for new visits."

The editor never strands the team without a visit form. Deleting the last form: "At least one form must remain. Add another form before deleting this one." Turning off the last form that is on: "At least one form must stay on, or there is no visit form to open. Turn another form on first."

If a delete would leave nothing on, another form is turned on for you: "Deleted. "General Clinic" was turned on so there is always a visit form."

Questions

  1. Tap Questions on a custom section.

  2. Type the label in the New question box.

  3. Pick a type: Short text, Long text, Single choice, Multiple choice, Number, Scale (0-N), Yes / No, or Date.

  4. Tap Add question.

    A row with arrows, a label box, the type list, a Required checkbox and Remove. Under it, the field id: "The field id is permanent; saved answers stay linked to it."

  5. Choice question: tap Choices and fill "Choices, one per line". It must keep at least one: "A question needs at least one choice. The previous choices have been kept."

  6. Scale question: tap Scale and set Lowest and Highest. A new scale runs 0 to 10.

  7. Tap Done.

Because the field id never changes, removing a question is safe for old records:

"Remove "Smokes"?

Answers already saved on existing records are kept, but this question will no longer appear."

If a change cannot be written, the editor says "That change was not saved:" with the reason, and "Your form is unchanged."

Formulary

The Formulary card is a table with the columns Medication, Dose, Unit, Category and Controlled, a Remove button per row, and the buttons Add medication and Save formulary.

One rule matters more than the rest. "Edit carefully: saved prescriptions keep pointing at the same entry, so never reuse a row for a different drug - add a new row instead."

Editing a row into a different drug silently changes what old prescriptions appear to say. Add new rows; remove rows you no longer stock.

ColumnWhat it does
DoseFills the dose box on the visit form when the drug is picked.
UnitDecides whether a dispensing quantity is counted: "tabs", "caps" and "sachet" count; "ml", "cream" or another unit records no quantity.

The formulary cannot be saved empty. After a save: "Saved 38 medications. Reopen the visit form to see them."

Lab tests and reference ranges

The Lab tests card defines the lab panel: a table with the columns Test, Type, Unit, On by default and Ranges, a Remove button per row, and the buttons Add lab test and Save lab tests.

A type is "Positive / negative" (POS and NEG buttons on the form) or "Number" (a number box with the unit as its hint). "Saving replaces the whole panel for your organization." The list cannot be saved empty.

Reference ranges: new results only

On a Number test, Ranges opens the editor headed Reference ranges. On a row not yet saved the button is off: "Save lab tests first, then set the reference ranges for this test."

The editor's standing notice governs everything here. "Changing ranges affects new results only.

Visits already saved keep the interpretation that was recorded at the time; editing ranges never rewrites a recorded result. Only new results entered after this change use the new ranges."

  1. Tap Ranges on a saved Number test.

  2. Add rows with Add range: a Label (for example "Normal"), From (at least), Up to (below) and a Color: None, Green (normal), Amber (caution), Red (critical) or Gray (neutral). An empty bound is open.

  3. Order the rows with the arrows; Remove drops one. "Ranges are checked top to bottom and the first match wins. A value equal to "from" is inside the range; a value equal to "up to" is not - it belongs to the next range up."

  4. Read the box headed "Check these before saving (saving is still allowed):". It lists a bound that is not a number, a range with no label, a range that can never match, two ranges that overlap, or a gap no range covers.

  5. Type a number under Try a value.

    Exactly what a new result would record: "Would record 182 mg/dL with interpretation Elevated".

  6. Tap Save ranges. Cancel asks "Discard the range changes?" if you have edited anything.

Diagnosis quick-picks and prescription presets

Both have their own cards under Settings, and both reach everyone on the next sync. Diagnosis quick-picks are the buttons under the Diagnosis box; each tap appends to the diagnosis text. Prescription presets are one-tap bundles in the Medications section: applying one adds its medication lines and treatment notes, and never removes lines already entered.

Hide or remove

Each entry is one row with ↑ and ↓, Hide or Show, and Remove. A hidden entry shows the word "hidden" on its row.

ButtonEffect
HideKeeps the entry, takes its button off the visit form; reversible with Show. Hover text: "Hidden entries stay in the list but do not appear on the visit form." (presets: "Hidden presets stay in the list but do not appear on the visit form.")
RemoveDeletes the entry. Saved visits are never touched, and the confirm says so.

"Remove "Dental Pain" from the diagnosis quick-picks?

Diagnoses already saved on visits keep their text - only the quick-pick button goes away."

"Remove the prescription preset "UTI"?

Prescriptions already saved on visits are kept, and the formulary is not changed - only the one-tap preset goes away."

Field ships with 31 quick-picks, "Malaria" to "Abscess", and 21 presets, "H. pylori Triple Therapy" to "MSK Pain". Built-ins can be removed too; the confirm adds "This is a built-in preset, so once saved it stays removed for your organization after sync."

For a cleaner form, hide instead of removing. An empty list is refused: "The diagnosis quick-picks cannot be saved empty. Hide entries instead if you do not want them on the visit form."

Nothing is written until you tap Save diagnosis quick-picks or Save prescription presets.

Adding a quick-pick

  1. Type it in the box with the hint "Add a diagnosis".

  2. Tap Add diagnosis or press Enter. The name box on each row is editable, so a typo can be fixed in place.

  3. Tap Save diagnosis quick-picks.

Building a prescription preset

  1. Tap Add preset, or Edit on an existing one.

    An editor under the list, headed "New preset" or "Edit preset".

  2. Type a Preset name; without one the editor says "The preset needs a name."

  3. Tap + Add medication per line. Pick the drug from the formulary list or the last entry, Other drug (type a name), which opens a Drug name box. Enter a dose, frequency and duration; × removes a line.

  4. Check the note under each line (table below).

  5. Fill Treatment notes added with this preset (optional) if wanted.

  6. Tap Add this preset or Apply changes, then Save prescription presets.

The device fleet

For teams whose devices sync through the organization's cloud project; a device set up on its own is in no fleet.

A device registers itself the first time it connects, in the wizard's cloud path or later with Connect this device to a cloud under Settings. Its name, role and last sync time land in the project's devices table.

The This device card shows the name, the Role, the first part of the Device ID, and the Mode ("Offline only" or "Cloud sync").

TaskWhereWhat to know
Rename a deviceRename this device on the This device card: a Device name box with Save name."Renaming keeps this device's identity: records it has already filed stay its own." It never re-registers, never orphans records.
Review the fleetThe project's SQL editor; the cloud sync guide has the one-query listing.Do it regularly: recognize every row, revoke strangers.
Revoke a lost or stolen deviceThe SQL editor, not the app.Records already pushed are kept. The app can never un-revoke a device; that lives only in the SQL editor, on purpose.
Change a device's roleThe devices table.The cloud's role is authoritative: the device adopts it on its next sync.

To replace a device, follow the Moving to a new device card under Settings:

  1. On the old device, tap Download backup and save the file somewhere you can reach it.

  2. On the new device, open the app and connect it to the same cloud project (or choose offline only).

  3. Tap Restore from a backup and pick the file.

  4. Check the record count matches before wiping the old device.

Honest limit: revoking does nothing to the data already on a lost device, and that data is not encrypted at rest. Treat a lost device as a disclosure, not just an access problem.

Backup and restore

A backup is a single file holding every record on the device plus the form and preset settings. It never contains the cloud key or device identity.

Take one at the end of each clinic day: it is the safety net if a device is lost, wiped or replaced. The admin's job is to make that habit stick on every device.

  1. Tap Download backup on the Backup and restore card.

    "Backup downloaded with 140 records. Keep it somewhere safe."

  2. Move the file (named dh-emr-backup and the date) somewhere safe.

With no cloud, the backup files are the organization's archive. With a cloud, the backup is still the true archive and the cloud a convenience copy for the devices; the cloud sync guide says why.

Restore merges; it never wipes

The card's own rule: "Restoring merges: nothing already on this device is lost, and where the same record exists in both the more recently saved version wins." A restore cannot undo newer work.

  1. Tap Restore from a backup and pick the file.

  2. Confirm the records restore.

    "Restore records from "dh-emr-backup-2026-10-06.json"? Records in the file are merged into this device. Where the same record exists in both, the more recently saved version is kept, so this cannot undo newer work."

  3. Answer the second, separate question about settings. Tap Cancel unless you are deliberately restoring configuration.

    "Also restore the settings from this file? That replaces this device's form layout, sites, providers and formulary with the ones in the backup. If this is an admin device those settings go out to the whole team on the next sync. Choose Cancel to restore records only. That is almost always what you want."

  4. Read the result.

    "Restored: 12 added, 3 updated, 125 already newer here. 140 records on this device. Settings were left as they are. Restored records will upload on the next sync."

On an admin device, restoring months-old settings and syncing would roll the whole team's forms, lists and formulary back.

Moving records from another cloud project

The Moving from another cloud project card brings records across from a project this device is not connected to, for example after moving to a new Supabase project.

  1. Export the records from the old project as JSON.

  2. Tap Import records from a file and pick the file.

    The records are merged in and upload to your current project on the next sync.

"Export as JSON, not CSV. CSV flattens lab results and medication lists into text and they cannot be read back reliably."

The demo

The Field demo runs entirely in the browser. Its banner: "A fictional clinic with sample patients. Everything stays in this browser and never syncs anywhere." It refuses every cloud connection: "Cloud sync is not available in the demo. This demo clinic is fictional and everything stays in this browser."

It skips the wizard and opens as an admin device named "Demo iPad" in offline-only mode: three sites, three clinicians, two forms on ("General Clinic" and "Mobile Outreach", each with its own custom sections) and ten visits for eight fictional patients, one with a name written in Amharic.

Rehearse here: try the template editor, build a preset, set a reference range, break things freely. Reset Demo in the banner puts the original sample patients back after a confirm.

Field as the backup for a Clinic organization

DH EMR Clinic depends on its internet connection. When the connection or the backend is down, the clinic sees patients on paper, and Field enters those charts afterward, at the end of the day, on any device with the Field app: typed up, searchable, counted in Analytics and backed up in a file.

There is no way to move Field records into a Clinic organization today. Data import from Field into Clinic is not available yet. Visits entered in Field stay in Field: not on the Clinic board, not in Clinic search, not in Clinic analytics.

Plan for thatWhy
Set up the Field device on its own, or give the Field devices their own cloud project. Never point one at the Clinic organization's project.A Clinic project only accepts signed-in accounts, so a Field device's uploads are refused there.
Keep the paper charts.If those visits are later needed in Clinic, the charts are the source and the Field records the typed copy.
Download a backup from the Field device after every day of entry.The files belong with the organization's archive.
Expect separate records even on one device.Field and Clinic keep separate records when both are installed on the same device. Nothing crosses between them.
